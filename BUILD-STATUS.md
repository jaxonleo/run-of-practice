## What this is

A live-practice-orchestration app for youth sports coaches: build a practice plan (drills, stations, timing), run it live with a timer/rotation system, share a read-only view with parent helpers, track attendance, and plan on a recurring schedule. React/Vite frontend, Supabase (Postgres + Auth + Realtime) backend, deployed on Vercel.

## Stack & repo layout

- **Frontend:** React 18, Vite, no CSS framework (hand-rolled CSS-in-JS injected via a `<style>` tag, Barlow Condensed/DM Mono fonts). No component library. `react-router-dom` v6 (data router) for navigation.
- **Backend:** Supabase — Postgres with row-level security on every table, Auth (email OTP), Realtime for live-session sync.
- **Deploy:** Vercel, auto-deploys `main` to production.
- `src/App.jsx` — still the largest file; holds the router, top-level `App()`, and several screens not yet split out (`TeamsScreen`, `BuilderScreen`, `PlayerProfile`, `RostersTab`, `AuthScreen`, `NameScreen`). Other major screens live under `src/components/`.
- `src/supabase.js` — the entire data-access layer. Every DB read/write goes through a named export here; nothing calls `supabase.from(...)` directly from a component.
- `src/constants.js` — pure helpers + shared constants (`uid()`, `TEAM_COLORS`, grouping math, `INIT` shape, `localDateStr()`).
- `src/Layout.jsx` — the authenticated app shell: global bottom tab bar, team-workspace top tab row, live-resume bar.
- `supabase/migrations/*.sql` — 144 migrations as of this session, each dated and mostly with inline comments explaining *why*, not just *what*. Applied via `npx supabase db push` (CLI is linked); some early ones were applied via the raw Management API and later reconciled with `migration repair`.
- `supabase/functions/*` — Edge Functions (Deno). First one added 2026-07-10 (`notify-team-staff-added`); a second (`notify-org-invite`) followed with the org model. A `_shared/emailTemplate.ts` holds the common Resend-email formatting both use. Secrets set via the Management API, never committed to migrations.
- `scripts/import-public-library.mjs` — one-time/rerunnable Node import script for the public drill catalog (see Library section below).

## Feature inventory (what actually works today)

### Auth & account
- Email OTP sign-in (code, not magic link — magic links broke for the installed-homescreen-PWA case). Branded email via Resend SMTP.
- One-time name capture on first sign-in (covers pre-existing accounts too).
- Soft account deactivation (reversible, auto-reactivates on next sign-in) and team deletion.

### Navigation
- Global bottom tabs: **Home / Teams / Library**, plus a gear icon (not a tab) to `/settings`. This replaced an earlier chips-on-Home team picker and a Manage-tab junk drawer — see Decision History.
- Inside a team workspace (`/team/:teamId/*`), the tab bar switches to a flattened horizontal top row of 4 direct routes: **Schedule / Roster / Equipment / Goals & Insights**. There is no more nested Plan/Team toggle and no Build tab — a `/team/:teamId/build` route existed as dead code (superseded by Home/Schedule's own "+ Practice" entry points) until this session removed it.
- A persistent live-resume bar renders across every route (not just certain screens) whenever a live session is in progress and the coach has navigated away without ending it.

### Teams & roster
- Teams have sport, timezone, season dates, and a color (auto-assigned from a curated palette, editable, includes black/dark gray) — shown as a Teams-list stripe and as the team-workspace header-bar background.
- The header bar's ellipsis is the only way to Edit Team; Delete Team (with a confirm step) lives inside the edit modal.
- Players, staff (head coach/assistant/helper roles), structured "Player Focus" areas (renamed from "Skill Notes") — skill-tag taxonomy + coach freeform sub-tags.
- Team creator is automatically head coach (trigger on team insert, personal teams only; one-time backfill already run for pre-existing teams).
- **Staff invite linking**: adding a coach by email (`add_team_staff` RPC) silently links to an existing account if one exists; a `claim_pending_team_staff` trigger auto-links any pending invite the moment the invited person signs up. Re-adding someone who left revives their archived row instead of duplicating.
- Invite notification email via a `pg_net`-triggered Edge Function + Resend (never Supabase's `admin.inviteUserByEmail`, which is a magic link).
- One-time welcome card + self-serve `leave_team` RPC (narrow — archives only the caller's own row, refuses for team owners).
- Staff-add suggestion chips (tap-to-fill staff already added on your other teams, deduped by email).
- Role-aware UI: assistants/helpers view everything and can run live sessions, but Builder/schedule-wizard/team-settings/staff-management entry points are hidden for teams they don't head-coach — checked per-team (`isHeadCoach`), not globally.

### Organizations (Coach/Org mode)
- `org_staff` is the org-membership table. Today it has exactly **one** role: the CHECK constraint only allows `'director'` — `admin` was proposed in the original design as a future extension (adding it later is a one-line constraint change, not a migration) but does not exist as a usable value yet. Don't assume an `admin` role is already live anywhere.
- A persisted (localStorage), per-device **Coach/Org mode toggle** on Home: Coach mode shows your own teams across every org; Org mode shows every team in one selected org plus a weekly-practices rollup. Only Home/Teams/Library change per mode — team-workspace screens never do.
- Org Details screen: name, sport, color, member list with an ellipsis-menu for add/remove/role-change ("Add Org Member" — an earlier "Invite Coach" label was renamed once it stopped being a no-op).
- **Coach invite flow** uses real consent, not the informal `team_staff` auto-link pattern: `org_invites` (pending/accepted/declined) → `accept_org_invite`/`decline_org_invite`/`cancel_org_invite`, with the caller's email matched server-side against `auth.jwt()`, never client-asserted.
- **Multi-org drill sharing** via `activity_library_org_shares` (a many-to-many join table, not a single-org column) + batch RPC `set_drill_org_shares` (all-or-nothing). `promote_drill_to_org_library` does a full-copy fork (director-only) — not a live reference.
- Library has a 5-tab sub-nav (Drills, Templates, Locations, Equipment, Skill Tags), each mode-filtered.
- Settings has "My Team Assignments": every team across every org, with a per-team `show_on_home` toggle to hide a team from Home without leaving it.
- **Known, unfixed gap**: Builder's own team picker is not mode-scoped (shows all teams regardless of Coach/Org mode).
- There is no standalone Org Home page — it existed briefly (`/org/:orgId`, `OrgHomeScreen.jsx`) but was retired and folded directly into `HomeScreen.jsx` under Org mode. Don't recreate it as a separate route.

### Library
- Drills, equipment/assets, templates — coach-owned, with org-sharing (see above) and manual drill reordering.
- **Skill tags**: `skill_categories` exists today for **6 sports** — Baseball and Basketball (seeded 2026-07-07) plus Football, Soccer, Lacrosse, and Volleyball (added 2026-07-18 alongside the Public Library taxonomy). Softball, Hockey, Tennis, and Swimming (the rest of the app's 12-entry sport list in `constants.js`) still have zero categories. All 6 categorized sports now work identically: real `scope='global'` tag rows, visible to every coach immediately, no per-coach action needed, and not individually archivable by any one coach (consistent across all 6 — see Decision History for the Baseball/Basketball duplication this replaced). `ensureDefaultSkillTags` (client-side, runs on every sign-in) still exists and is still called, but is currently a no-op for every sport — kept in place rather than removed, in case a future sport ever wants true per-coach starter tags again.
- `SkillTagPicker`: selected tags show as removable chips; an "Add/Edit Skill Tags" button opens a full category-grouped, searchable picker in a bottom-sheet overlay.
- **Public Library** (built and shipped — the planning doc for this feature was written before implementation and is now stale on this point): a `content_catalogs` table backs a search-first Public Library browser (`PublicLibraryScreen.jsx`, 2026-07-19) — pick a sport first, never a dump of every drill; working Source/Publisher filters (currently one option each, future-proofed for multi-publisher catalogs); founder-admin add/edit/archive affordances built in. Seeded via `scripts/import-public-library.mjs` from the per-sport JSON files in the repo root (`ROP-Public-Library-*.json`). `copyDrillToMyLibrary` resolves a copied drill's equipment into the recipient's own asset pool by name-match-or-create; it does **not** currently copy skill tags of any scope onto the copy (a known gap, not yet fixed).

### Planning & scheduling
- **Builder**: practice/template editor — drills, checklist activities (intro/closer), station blocks with rotation, grouping (whole/partners/N groups), equipment, coaching points, per-activity coach/sublocation assignment.
- **Recurring schedules**: a wizard (days of week → time/duration → date range defaulted from team season → location → preview with per-date deselect) backed by `create_practice_series` — atomic, server-capped (≤150 occurrences, ≤400 day range), timezone-correct (DST-safe via `AT TIME ZONE`).
- **Home screen**: adaptive hero card for the next practice (Plan/Review/Run depending on state), an "Upcoming Practices" list on a **7-day** rolling window (renamed from "This Week" once the team realized the underlying filter was never a calendar week), and a separate "N practices need a plan" nudge that intentionally uses a **14-day** window (wider, so the nudge has real run-status data before a practice is imminent) — these are two different, deliberately different windows, not a contradiction.
- **Schedule tab**: Agenda (day-grouped, team-color-coded dots) and Month (calendar grid with per-day dots) views, both using the same hollow-when-unplanned/filled-when-planned dot rule.
- **Planned absences**: capture from Practice Detail, Player Profile, or a Home quick action. Feeds Builder's default group assignment and the live session's attendance defaults.
- Cancel (this-occurrence or this-and-future for a series) / restore; a "missed" state for practices whose time passed with no run.
- All practice times display in the **team's** timezone, never the viewing device's; "today" is always computed via `localDateStr()` (local calendar day), never `.toISOString()`.
- **Planning-depth indicator**: any practice with a `scheduled_duration_minutes` shows "35/60 min" whether planned or not. Plain binary: red under 90% planned, green at or above it — purely derived (`planningState()`/`sumMins()`), never stored. The green state keeps a `✓` glyph; the red state deliberately has **no** icon (see Decision History for why not `⚠`).
- **Getting-started checklist**: a single "?" icon on Home, opening a 5-step checklist (team → roster → schedule → first plan → first live run), fully derived from existing data, no stored progress flags.

### Goals & Insights
- Lives as a sub-toggle inside a team's Plan-equivalent workflow (folded together because "how this team spends its practice time" covered both, and Goals' original placeholder scope had never been built out separately).
- Coach sets per-skill-tag target percentages (category-grouped picker filtered to the team's sport, sum-over-100 validated), plus a 1–12 week rolling report window (`teams.goals_window_weeks`).
- A bullet-chart-style glance view: target tick, planned/actual bars, delta chips (only shown at ≥3 points off), an "untagged" row, an "other/transitions" per-practice average.
- A History section, backed by `get_team_session_history(team_id)`, is the first real frontend read path for `session_activity_log`'s actual (not just planned) timing: reverse-chronological sessions with wall-clock duration, attendance, top-3 skills, and manager-only editing (exclude a session from goals, adjust a logged row's start/end, or log a row that was never captured live).
- The older, separately-used `HistoryViewer` component (`CommandScreen.jsx`, reused by `ScheduleScreen`/`ManageScreen`) was deliberately left untouched rather than retrofitted with this — it only ever receives a bare `practice` object, no `session_id`, so a new `SessionHistoryDetail` component was built instead to avoid destabilizing three already-working call sites.

### Live sessions
- Real-time state machine (`practice_live_sessions`) with take-control/hand-off between coaches, pause/resume, ±1 min nudge, station rotation, append-only attendance (`session_attendance`), and per-activity dwell-time logging (`session_activity_log`).
- Offline resilience: single-pending-write retry with backoff, distinguishes "network down" from "someone else moved the session" so a signal drop doesn't blank the screen.
- Mid-run plan editing (`LiveEditBuilder`).
- A coach can leave a live session without ending it — safe because the whole run state (timer, stage) re-derives from `current_phase_started_at` on mount, not from anything held only in memory.
- **Audio cues** (coach view only): a silent background `<audio>` loop + Screen Wake Lock keep the tab alive when the phone locks; real audio files (`tennis-beep.wav`, `gym-buzzer.wav`) play for the 2-minute warning and time's-up, alongside or instead of `speechSynthesis`. `HelperView` (parent-facing) is still speech-only — not yet extended with the same treatment.

### Helper/parent-facing (anonymous, token-based, no login)
- `/preview/:token` — pre-practice setup view (equipment, roster, countdown to start).
- `/live/:token` — live view during a run (current drill/station, roster, optional attendance-marking scope).
- Player data is minimized (first name + last-initial + jersey), everything else (equipment, coaching points, location) is shown in full — a deliberate privacy choice, not an oversight.

### Public landing page, feedback, and legal
- `/` is adaptive on session state: signed-out renders `LandingPage`, signed-in renders the app — deliberately not a hard route split, so an installed PWA icon (`start_url: '/'`) keeps launching straight into the app.
- Landing page is a full 14-section product-walkthrough marketing site with real app CSS-class-built visuals (not screenshots, not stylized mockups) using realistic sample data — pixel-consistent with the actual UI by construction.
- `/terms`, `/privacy` render final, attorney-cleared copy via a single catch-all `vercel.json` rewrite.
- In-app feedback is authenticated only (Home "?" → "Send Feedback"). The landing page's own anonymous feedback form was removed; `submitPublicFeedback`/`feedback` table are deliberately left in place, unused, in case a future non-authenticated contact path wants them — this is the one piece of intentionally-kept dead code in the app (left alone in this session's cleanup for that reason).

## Database & permissions (architecture, not a live snapshot)

Point-in-time row counts and table counts age out fast on a system under active development — the last full live-DB introspection was 2026-07-21, and several sessions have touched the schema since (the org-model rework and Coach/Org mode work alone add and drop tables/columns). What's stable and worth keeping here is the **architecture**, not a specific count. Run a fresh introspection against the live project before trusting any specific number.

**Ownership patterns**
- **Team-scoped**: practices, stations, session data — access via `can_access_team`/`can_manage_team`, which check `teams.owner_user_id`, org membership (`teams.organization_id` + `is_org_member`/`is_org_admin`), or a non-archived `team_staff` row.
- **Coach-or-org ("owned")**: drills, assets, locations, templates, skill tags — `owner_user_id` XOR `organization_id`, checked via `can_access_owned`/`can_manage_owned` (the latter requires org-admin, not just org-member, for org-owned rows — keeps shared libraries curated).
- **Anonymous/token tier**: `session_access_tokens` (scope, expiry, revocation) gates `/preview/:token` and `/live/:token` entirely through `SECURITY DEFINER` RPCs — `anon` has no direct table grants beyond `REFERENCES/TRIGGER/TRUNCATE` on real tables.
- **Platform admin**: `admin_users`/`is_admin()` is a flat, separate superadmin gate (founder metrics, public-catalog curation rights) — unrelated to org roles.

**RLS conventions used everywhere**
- Almost no DELETE policy anywhere — archive via `archived_at`, never hard-delete through the app. Exceptions: join tables where removing an association isn't destroying history, and one explicit audit-adjustment delete policy on `session_activity_log`.
- Actor-identity columns (`created_by`, `marked_by`, `noted_by`, etc.) are enforced via `WITH CHECK (col = auth.uid())`, never trusted from the client.
- `service_role` bypasses RLS entirely but **not** base-table GRANTs — every new Edge Function or import script that queries app tables directly (rather than through an RPC, which runs as the function owner) needs its own explicit grant. This has bitten more than one session (first `profiles`, later `org_invites`/`organizations`) — check for it early if a new Edge Function mysteriously returns empty/errors.
- `practice_activities`/`template_activities` are full copies of the source drill's fields at add-time, never live references — editing a library drill or template later never retroactively changes anything already built from it. Same lineage-not-binding pattern applies to `templates.default_team_id` and `practices.template_id`.

**Legacy POC tables — dropped 2026-07-27.** `app_data`, `coaches`, and `live_sessions` (the old table) predated the current migration history entirely (created for the pre-rewrite POC, before Postgres RLS/auth existed in this app) and had carried their original wide-open `anon`-era RLS the whole time. Once `app_data`'s last client-side reference was traced and removed (see Decision History), all three were confirmed zero-reference in `src/`, and dropped via `20260727000000_drop_legacy_poc_tables.sql`. If you're looking for them, they're gone on purpose — see Decision History for the verification trail before dropping.

## Working conventions

- No client-side insert loops for bulk operations — always one atomic, server-capped RPC (`create_practice_series` is the model to copy).
- "Archive, don't delete" (`archived_at`) almost everywhere; see RLS conventions above for the exceptions.
- Migrations are always dry-run (`BEGIN;...;ROLLBACK;`) before applying for real, and applied via `npx supabase db push` (the CLI is linked in this environment). If a migration is ever applied via the raw Management API instead, run `migration repair --status applied` before the next `db push --dry-run`, or the CLI will misjudge it as pending.
- Testing pattern for anything requiring a signed-in user: a disposable Supabase test account via the Admin API's `generate_link` + `verifyEmailOtp`, verify via direct SQL, delete after. Never test destructive flows on the real coach's account. Note: `generate_link` and the app's own "Send Code" share a rate-limit bucket.
- Timezone: always compute/display via the team's own `timezone` column, through `scheduledAtToTeamLocal`/`teamLocalToScheduledAt` — never the viewing device's zone, never bare UTC truncation (`localDateStr()` exists specifically to avoid the UTC-rollover bug described in Decision History).
- Secrets never go into migration files (git-tracked) — Vault or Edge Function secrets only. A `pg_net`-triggered function needs `verify_jwt:false` plus a shared-secret header.
- `.upsert()` still needs an UPDATE grant even for `ON CONFLICT DO UPDATE` — use `{onConflict, ignoreDuplicates:true}` when a table's RLS is insert/delete-only by design.

- **A second, dedicated verification pass** (triggered by a direct question — "only Baseball/Basketball have categories" didn't match what the user knew to be true) re-checked every concrete factual claim in the Feature Inventory and Known Gaps sections against migrations/code directly, rather than trusting the first pass's synthesis. It found and fixed four more real errors, all now corrected in place above: (1) `skill_categories` actually covers 6 sports, not 2 — a 2026-07-18 migration added Football/Soccer/Lacrosse/Volleyball, and the per-coach tag-seeding function was never updated to match, so Baseball/Basketball coaches likely get duplicate-looking tags (personal copy + global) while the 4 newer sports don't; (2) `org_staff.role`'s CHECK constraint only allows `'director'` — `admin` doesn't exist as a value yet, despite being described as already-differentiated; (3) `app_data` was wrongly described as dead/unreferenced — it turned out to be the live backing store for `App.jsx`'s legacy `data`/`update()` state (see the next entry for the full trace and its resolution); (4) a wrong Edge Function name (`org-invite-notify` → `notify-org-invite`). The root cause across all four: the first pass verified some claims against code/git directly but carried others over from the source docs' own framing without redoing that check.
- **Full trace of `App.jsx`'s legacy `data`/`update()` state, and its removal.** Asked to finish what the second verification pass started: what does `app_data` actually still do? Traced `fullData` (`App.jsx`, what every screen actually receives) to `Object.assign({},data,{teams},library,planning)` — since later arguments win, `library`/`planning` overwrite every field they share a name with (`teams`, `locations`, `assets`, `activityLibrary`, `templates`, `practices`), so the *only* survivor from the raw `app_data`-backed `data` object was `.notes`, and nothing read it once `NotesTab` was gone (previous entry). On the write side, a repo-wide grep for actual `update(...)` invocations (not just the prop being passed around) found exactly one call site, inside `ModalLayer.jsx`'s `"editTemplate"` modal branch — and that modal type was never once opened anywhere (`openModal("editTemplate", ...)` has zero call sites; its sibling `"addTemplate"` had no submit handler at all even if reached). Templates are actually edited today through `TemplateWorkspace` (`NewLibraryScreen.jsx`, a real `saveTemplateTree`-backed flow) — the modal branch was a leftover from before that existed. Removed the dead modal branch (variable, submit handler, form JSX, two orphaned `TITLES` entries), which left `update()` with zero call sites anywhere in the app.
  
  With both sides of `app_data` proven dead, removed the whole pathway: `data`/`setData` state and the `update` callback in `App.jsx`; `loadData`/`saveData`/`flushSave`/`setCoachKey` in `supabase.js`; `INIT`, `DEMO_INIT` (an entirely unused demo-coach seed object — not imported anywhere despite a comment claiming otherwise), and `migrateData` (a shape-repair function for the old blob, still carrying a hardcoded `c_jaxon2`→`c_jaxon1` id fix from the pre-rewrite POC era) in `constants.js`; and the now-pointless `update` prop threaded through `HomeScreen`, `ScheduleScreen`, `RostersTab`, `BuilderScreen`, `CommandScreen`/`HistoryViewer`, `PracticeDetail`, `NewLibraryScreen` (which didn't even destructure it), and `ModalLayer`. `fullData` was renamed to plain `data`, now built directly from `teams`/`library`/`planning` with no `app_data` blob underneath it at all.

  One real behavior change, not just deletion: `loaded` (gates the "Loading your data..." spinner) used to flip once `loadData()` resolved. Re-wired to a single effect that runs `Promise.all([refreshTeams(),refreshLibrary(),refreshPlanning()])` on `coachId` change and flips `loaded` after all three resolve — the three individual mount-triggering effects that used to call each one separately were folded into this one. Verified via `npm run build` (clean, slightly smaller bundle) and a dev-server load of the signed-out landing page (no console errors) — the signed-in `loaded` path itself couldn't be click-tested, same standing credentials limitation noted throughout this file's history.

  **This shipped a real production incident.** `Promise.all` has no `.catch()` — a rejection in any one of the three fetches leaves `loaded` stuck at `false` forever, since `.then()` never fires. The old gate never had this failure mode (it was checking something fully decoupled from these three fetches), so this was a new bug introduced by the refactor, not a pre-existing one surfaced by it. It hit in production immediately after deploy (app stuck on the loading screen for the real user). Fixed same-day by switching to `Promise.allSettled`, which always resolves regardless of individual rejections — logs which fetch failed via `console.error` rather than silently hanging. Lesson for next time this pattern comes up: gating UI on `Promise.all` of several independent data fetches is only safe if every one of them is guaranteed to resolve (they're not, in general) — `allSettled` (or a per-fetch `.catch()`) is the default-safe choice.

- **Legacy POC tables dropped** (`app_data`, `coaches`, old `live_sessions`) once `app_data`'s last reference was gone (previous entry). Before dropping anything on the live production database, verified rather than assumed: queried current row counts (5/2/76, matching the already-documented orphaned-POC snapshot), checked `app_data`'s actual keys and confirmed none matched the real coach's actual `auth.users` uuid (all were old POC-era ids like `coach_coach_demo_wwql`), and ran the `DROP TABLE` wrapped in `BEGIN;...;ROLLBACK;` first to confirm no dependency errors (views, FKs) before committing to it for real. Also had to reconcile 2 migrations (`20260724000000`, `20260724010000`) that were already live in the schema but unrecorded in the CLI's migration-history table — the exact drift this file had flagged as pending since the 2026-07-21 session — via `migration repair --status applied` before the drop migration could push cleanly. Applied via `supabase db push`; confirmed post-drop that all three tables are gone and the new migration is correctly recorded with no new drift.

- **Baseball/Basketball skill-tag duplication, fixed.** Root cause confirmed by querying the real coach's actual tags directly rather than reasoning about it in the abstract: every Baseball/Basketball category had an identically-named `scope='coach'` row (from the 2026-07-11 per-coach seeder) sitting next to the `scope='global'` row the 2026-07-18 migration added — 947 duplicate rows across all 17 coaches who'd ever signed in (mostly disposable test accounts), confirmed via direct query before touching anything. A coach's own genuinely custom tags were never at risk — the fix only ever matches on an *exact* `(category_id, name)` collision against an existing global tag, so tags like "Passing on the move," "Layups," "Cutting," and "Transition defense" (none of which are in the seed function's hardcoded list) were confirmed untouched afterward.

  Before deleting anything, checked what actually referenced the duplicate rows: 15 real `drill_tags` rows pointed at a duplicate instead of its global twin (0 `player_focus_areas` rows did). Deleting the duplicates outright would have cascade-deleted those 15 real tag associations (`drill_tags.skill_tag_id` is `ON DELETE CASCADE`), so the migration re-points them to the global tag first — dropping only the rare case where a drill was already tagged with *both* the duplicate and its global twin (which would otherwise violate `drill_tags`' `UNIQUE(activity_library_id, skill_tag_id)`) — then deletes the now-unreferenced duplicates. Dry-run confirmed `drill_tags`' total row count was identical before and after (202), meaning every real tagging survived, just re-pointed.

  `seed_default_skill_tags_for_coach` was also updated (`CREATE OR REPLACE`) so it no longer special-cases Baseball/Basketball — every sport now falls through to the same empty-array no-op. The function and its trigger are kept in place rather than removed, since `ensureDefaultSkillTags` is still called client-side on every sign-in and a future sport could legitimately want true per-coach starter tags again; today it just does nothing for any sport, matching how Football/Soccer/Lacrosse/Volleyball already worked. Applied via `supabase db push`; confirmed post-migration that zero duplicates remain, `drill_tags`' count is unchanged, and the coach's real custom tags are intact.

### Auth
- Email OTP chosen over magic links specifically because magic links broke for the installed-homescreen-PWA sign-in case. `admin.inviteUserByEmail` is avoided for staff invites for the same reason (it's a magic link) — a custom `pg_net` + Resend Edge Function handles that notification instead.

### Skill tags & taxonomy
- Skill tags are seeded as **personal** `scope='coach'` copies per coach rather than true `scope='global'` rows: global rows are only writable by `service_role`/`is_org_admin` under existing RLS, so one coach archiving a shared global tag would silently remove it for every other coach. Per-coach seeding sidesteps that with zero RLS changes, reusing the machinery that already existed for a coach's own custom tags. `ensureDefaultSkillTags` re-runs (idempotently) on every sign-in so a coach picks up new tags from later migrations, not just what existed at signup.
- `skill_categories` has no app-level INSERT policy anywhere, by design — Jax seeds/curates these directly. This is why 4 of the app's 12 sports (Softball, Hockey, Tennis, Swimming) still have zero taxonomy: nobody has seeded them yet, not a technical blocker.
- A unified taxonomy and public-catalog drill content were drafted for a 6-sport initial pass (JSON-per-sport deliverable, so 150+ drills could be imported mechanically rather than hand-transcribed) with category names deliberately reused across sports on purpose (enables cross-sport reporting). A system publisher profile (e.g. `content@runofpractice.com`) was the chosen design for content attribution over relaxing ownership constraints — real `profiles` row means the existing `activity_has_owner` constraint needs no changes, and gives real "Published by Run of Practice" attribution for free. **This plan is what became the shipped Public Library feature** (see Library section above) for Baseball, Basketball, Football, Soccer, Lacrosse, and Volleyball — the original planning doc undersold this by never being updated to say so. Softball/Hockey/Tennis/Swimming were never part of this pass and still have no categories, tags, or public-library content.

### Sharing & org model (schema evolved twice — read in order)
1. **Original design (2026-07-06)**: a single `shared_with_organization_id` column on `activity_library`/`templates` — private by default, share with exactly one org, org-owned "Org Library" kept as a separate concept from coach-owned-shared-into-org "From Our Coaches." Public visibility explicitly deferred entirely (became the Public Library work above). The "copy, don't reference" rule was set here specifically to avoid a shared thing referencing something its viewers can't see (this bug class was hit five times during the original schema build) — copying a shared drill resolves equipment by name into the recipient's own pool rather than pointing at the sharer's rows.
2. **First org-model implementation (2026-07-21)**: `organization_members` (owner/admin/coach/viewer, zero real rows ever) was replaced wholesale by `org_staff` (single `director` role, extensible without a migration later). New RPCs (`org_create_team`, `org_assign_team_staff`, `org_assign_player`) were added as explicit auditable entry points, even though the underlying RLS already permitted an org-admin's direct write — deliberately not narrowed, since narrowing wasn't asked for. The single-org `shared_with_organization_id` column was recognized as insufficient the same day (a coach can be director of one org while coaching a team in a different org — a single column can't hold "share with more than one"), so it was replaced by the `activity_library_org_shares` join table before this design ever shipped as originally spec'd. `org_invites` got a real accept/decline consent flow (never the informal `team_staff` auto-link pattern) specifically because joining an org is a bigger commitment than being added to a team roster.
3. **Rework into Coach/Org mode (later session)**: the standalone Org Home page (`/org/:orgId`) was retired and folded directly into `HomeScreen.jsx` behind a persisted Coach/Org toggle — this is why `fetchPendingOrgInvites`/`orgAssignTeamStaff`/`orgAssignPlayer`/`promoteDrillToOrgLibrary` ended up as dead exports (superseded by different call patterns) cleaned up in the thirteenth session above. Team/asset/location/skill-tag creation inside Org mode reuses the same coach-or-org ownership pattern the rest of the app already had (`createOrgLocation`/`createOrgAsset`/`createOrgSkillTag` — no new RPCs needed, existing RLS already permitted a director's direct insert with `organization_id` set).

### Navigation (restructured multiple times — read in order)
1. Home originally had a pill/chip row for picking a team — removed entirely (not reskinned) once direct user feedback said it read as a filter control (tap to toggle in place) rather than navigation (tap to leave the page). Replaced by a dedicated global **Teams** tab, reachable from anywhere including Library.
2. The team workspace went from a 4-tab shape (Schedule/Plan/Goals/Team) to a 3-tab shape (Schedule/Plan/Team, Goals folded into Plan as a sub-toggle) — Plan's original scope had never actually been built past a placeholder, so nothing real was lost merging it in. Team Equipment/Player Gear moved out of global Settings into the Team tab and became sport-aware (auto-stamps the current team's sport, filters lists to `sport === team.sport || 'General'`) once showing all-sport gear while coaching one team's context was flagged as "weird." Skill Tags and Locations stayed in global Settings deliberately — they're coach-wide vocabulary/resources with no team ownership in the schema, so editing them from inside one team's context risked silently rippling to every other team.
3. Later flattened further: the nested Schedule/Plan/Team (with Plan hiding a Build/Goals toggle, Team hiding a Roster/Equipment toggle) became 5 direct top-row routes so nothing was two taps deep — then reduced to the current 4 (Schedule/Roster/Equipment/Goals & Insights) once Build's tab-bar entry was dropped as redundant with Home/Schedule's own "+ Practice" entry points (its route/component lived on as dead code until the thirteenth session).
4. The original `App.jsx` `view`-string state machine with manual `window.location.pathname` regex checks was replaced by real `react-router-dom` v6 routes; the `guardedSetView`/`priorView` unsaved-changes mechanism was replaced by `useBlocker` + `beforeunload` (the old mechanism never protected against a hard refresh or tab close either).
5. The old single "Manage" screen mixed coaching content and one-time setup in one junk drawer. Split: `SettingsScreen.jsx` (Account, Locations, Equipment & Gear, Skill Tags) for setup; Library's My Library/Explore structure for content; `ManageScreen` now purely serves the team workspace's Team tab. A critical catch made during planning, not after: the old Manage "My Teams" list held the app's only reachable "+ Team" button — it was rehomed onto the new Teams tab's header before the old list was deleted, not after.

### Live sessions & timing
- The "leave a live session without ending it" feature was judged safe specifically because the live-run timer/stage was already fully re-derived from `session.current_phase_started_at` on mount (built earlier for multi-coach handoff/reconnect) — unmount/remount naturally resumes correctly, no separate persistence needed.
- Real audio-cue files via `<audio>` elements plus a silent background loop were chosen over an earlier, abandoned approach (a raw `AudioContext` oscillator tone) because Safari blocks Web Audio output but has a real background-audio exemption for actual media elements. The new tone was added strictly additively alongside the existing, working `speechSynthesis` cues first, specifically so a tone failing on some device wouldn't break the fallback — the redundant spoken "Next up!" cue was only removed later, after confirming the tone worked. `HelperView` (parent-facing) was deliberately not given the same treatment — the original complaint was specifically about the coach's own phone locking mid-session.
- `session_activity_log` has no stored/computed duration column (duration = `ended_at - started_at`, null if never explicitly ended) and no backfill/cleanup mechanism for a dangling open row from an abandoned session — flagged as needing a product decision (exclude? clamp to session end? clamp to now?) with no existing convention to follow yet.

### Bugs whose root cause is worth remembering
- **Drill/equipment tags "not persisting"**: `syncDrillTags`/`syncDrillEquipment` never checked `.error` on insert/delete, so a rejected write (e.g. a failed RLS check) looked identical to success — the modal closed and data silently reverted. Not a broken permission model; purely missing error surfacing. Fixed by propagating `{error}` through the whole chain and keeping the modal open with a visible error on failure.
- **"Today" rolling over early for western-hemisphere coaches**: `new Date().toISOString().slice(0,10)` converts to UTC before truncating, which rolls "today" to the next calendar day hours before local midnight west of Greenwich (surfaced by a Phoenix, UTC-7 coach). Fixed with `localDateStr()` (same local-getter construction Month view's grid already used correctly) swapped in everywhere the UTC pattern appeared.
- **Team creation broken for any coach with no last name**: the auto-head-coach trigger copied `profiles.last_name` (optional) straight into `team_staff.last_name` (`NOT NULL`), silently rolling back the whole `teams` insert with no UI error. Fixed with `coalesce(...,'')`.
- **Schedule duration field un-typeable**: `+e.target.value || 60` meant clearing the field to type a new number evaluated to `60` on every keystroke (`+"" || 60`), so a coach could never get past the leading digit. Fixed by allowing a transient empty-string state, defaulting only on blur/submit.
- **iOS auto-zoom on some inputs but not others**: the shared input font-size was 15px, one pixel under the 16px threshold where iOS Safari auto-zooms on focus. Bumped to 16px app-wide.
- **`org_staff` member list silently empty**: the table has two FKs to `profiles` (`user_id`, `invited_by`), so a bare `profiles(...)` PostgREST embed was ambiguous and errored — silently swallowed by the function's own `catch`, returning `[]`. Fixed with an explicit `profiles!org_staff_user_id_fkey(...)` hint.
- **A director seeing a stranger's pending org invite**: `org_invites_select`'s RLS deliberately lets a director see every pending invite for orgs they administer (needed for a sent-invites list) — but the client rendered all of those as if addressed to the viewer. Fixed by filtering client-side to the caller's own verified email, matching the same server-side-truth principle the accept/decline RPCs already use.
- **The under-planned pill's warning glyph**: `⚠` (U+26A0) renders with its own built-in emoji-yellow color in most browsers regardless of the CSS `color` applied to it — looked like a permanent yellow warning triangle no matter the pill's actual state. Removed; the red under-planned state deliberately has no icon now. Don't reintroduce one there without checking it isn't in the emoji-default-presentation set.

### Operational gotchas worth not re-learning
- `supabase config push` (verified against the actual Supabase CLI Go source, not guessed) unconditionally overwrites only `site_url`/`additional_redirect_urls`; everything else (SMTP, email templates, MFA) is nil-gated and untouched unless locally set in `config.toml`. Piping `"n"` to its interactive per-service confirmation prompts did **not** reliably decline in past testing — treat any piped-input dry run against this CLI with suspicion.
- `service_role` bypasses RLS but not base-table GRANTs (see RLS conventions above) — this has caused silent empty results from more than one new Edge Function.
- No automated test suite exists anywhere in this project, by design — there's no local Supabase environment in this setup, so everything is verified empirically in a live browser against production, using disposable test accounts, before being called done.
